The half that needs no model

Is this word spelled two ways across the project. Does this figure still match the command that produced it. Was this paper retracted.

Nobody has to read anything to answer those. Twenty-five commands ship as a CLI with no dependencies. They run in your build and they stop it.

stet sums, run on this repository 
7 relations across 61 files.

7 consistent, 0 wrong, 0 worth a look
NOT CHECKED  2 relations inside quotation
             marks, 1 on a marked line

Every command tells you what it skipped. Say nothing and a person reads it as nothing to do, which is a different thing and not true.

One

What each one catches

Ten of them do the work you would notice. The other fifteen are plumbing: what content exists, who owns it, what the style sheet decided, what to set on a file.

Each one was run over this whole repository and tuned until it stopped crying wolf. A check that fires on work you got right is a check you switch off, and then it protects nothing.

stet help <command> prints the full reference for any of them.

CommandThe thing it catches
checkA product name spelled two ways across forty files
auditThe sweep, ranked by what it costs you
verifyA number typed by hand where a source was declared
sumsParts that do not make their total, and statistics that disagree with their own p-values

Two

Why this is worth a build step

Somebody counted all four of these. The numbers are worse than anyone guesses.

The link one catches people out. A URL that still returns 200 has not necessarily kept the sentence you cited it for. The page looks fine. Nothing on it says the paragraph you quoted came out two years ago.

So standing writes down what a source said the first time you cited it, and tells you what has changed since.

FigureOf whatSource
76.35% References whose content had drifted, 184,065 of 241,091 Jones and others, PLOS ONE, 2016
70%+ URLs in the Harvard Law Review no longer reaching the material, and 50 percent in Supreme Court opinions Zittrain, Albert and Lessig, 2014

Three

Running it

You start with one file, stet.config.json. It says which files are your words. It can also say where a figure comes from, which is a shell command.

The record then lives in the content itself. In the frontmatter where the format has it, in a stet key for JSON, in a small file alongside for everything else. Nothing else in the file moves.

Stet touches your words and nothing else. No components, no routing, no CSS. Put it on Next, Astro, Hugo or a folder of Markdown and it behaves the same.

In a build 
# everything, exit 1 on a disagreement
stet audit

# or pick the ones you care about
stet check && stet sums && stet standing

# one file, against your own voice
stet measure docs/pricing.md

The CLI ships inside the plugin, and node bin/stet.mjs from a clone works the same. No network for the checks that do not need one.
